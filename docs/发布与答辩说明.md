# GitHub 发布与课堂答辩

## 发布

建议仓库名：`coursemate-langchain`，可见性选择 Public。

如果已经连接 GitHub，可以让助手协助发布。未连接时，在 GitHub 登录并创建空仓库，然后在项目目录执行以下命令，把 `YOUR_USERNAME` 替换成真实用户名：

```powershell
git init
git add .
git commit -m "Initial CourseMate LangChain application"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/coursemate-langchain.git
git push -u origin main
```

如果项目已初始化或已经提交，跳过对应命令。如果没有配置 Git 身份，先用自己的姓名/昵称和邮箱配置 `git config user.name`、`git config user.email`。GitHub 的登录认证需由账号本人完成。

发布后：

1. 用实际仓库地址替换 README 开头的待发布说明。
2. 提交并推送更新后的 README。
3. 打开公开仓库确认能访问 README 和代码。
4. 将 README 上传至课程作业系统，并附带实际仓库链接。

不要上传作业文件夹外层的课件、课件完整抽取文本、虚拟环境或真实密钥。只发布 `coursemate` 项目目录。

## 答辩提纲

- 应用解决什么问题？让课程资料可检索，并用大模型将相关原文组织成易读答案。
- LangChain 在哪里？`core.py` 中使用 Document、RecursiveCharacterTextSplitter、ChatPromptTemplate、MessagesPlaceholder、ChatDeepSeek/ChatOllama、StrOutputParser。
- 为什么叫 RAG？先从外部资料检索相关片段，再把片段与问题一起输入大模型生成答案。
- 为什么不使用 Chroma？小型作业选择 TF-IDF 内存索引，降低部署成本；检索层可以替换。它没有神经语义嵌入的能力。
- 如何减少幻觉？限制资料范围、无检索结果直接拒答、提示引用编号、显示原文。仍需人工核验。
- 在线和离线区别？在线依赖服务商 API 与额度；离线依赖本机模型和硬件，已下载后可以不联网。
- 测试通过说明什么？说明被覆盖的解析、检索和程序数据流正常；模拟模型测试不能代表真实生成效果。

## 建议保留的演示材料

使用真实模型完成一次资料问答，保存学习记录，并截取显示模型模式、问题、回答和来源的界面。截图避免包含 API Key。课程若未要求截图，README 与真实仓库链接仍是明确要求的提交项。
