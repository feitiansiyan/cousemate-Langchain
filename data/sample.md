# 软件工程学习笔记（项目原创示例）

## LangChain 的职责
LangChain 是构建大语言模型应用的开源框架。它把提示模板、聊天模型、输出解析器和检索组件组合起来。ChatPromptTemplate 管理提示词，Document 保存文字与来源元数据，StrOutputParser 将模型输出解析为字符串。LCEL 可以用 prompt | model | parser 表达一条可调用的链。

## RAG 的基本流程
RAG 即检索增强生成。先加载文档并按长度切分，再为片段建立可搜索的索引。用户提问后，检索器选出相关片段，提示模板把片段和问题交给大模型，大模型依据资料生成答案。RAG 无需为每次资料更新重新训练语言模型。返回来源文件和页码能够帮助用户核验答案，但不能保证完全消除幻觉。

## 分块和重叠
长资料需要分块，否则可能超出模型上下文窗口。chunk_size 控制片段长度，chunk_overlap 让相邻片段保留部分重复内容，减少边界处的信息丢失。片段太小会缺少上下文，片段太大会引入无关内容。课伴采用 700 字符分块和 100 字符重叠。

## 在线与离线模型
在线模式调用服务商 API，无需自行加载模型权重，但需要网络、密钥，并可能产生费用。离线模式在本机运行已下载的模型，资料可以留在本机，但受内存、显存和处理器性能限制。首次下载模型和安装依赖仍然需要联网。Ollama 提供本地模型服务接口。

## 检索的选择
TF-IDF 根据词项频率和逆文档频率计算向量，余弦相似度衡量文本相近程度。中文字符 n-gram 不依赖中文分词词典，适合课程原词查询。它不等同于神经网络语义嵌入，对同义词、隐含意图和跨语言问题的效果有限。可进一步替换为嵌入模型与向量数据库，并用带标准答案的问题集评价召回率。

## 软件测试与密钥管理
单元测试可以验证文件解析、分块、检索和链式数据流。使用模拟模型的测试不证明真实模型效果。真实调用需要另行检查鉴权、连通性和回答依据。API Key 应保存在环境变量或被 Git 忽略的 .env 中，不应硬编码进程序或上传到公开仓库。
